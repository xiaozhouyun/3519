# ST7735S SPI Timing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以约 1 MHz SPI 与 DC 切换稳定时间验证 ST7735S 花屏是否由总线时序裕量不足导致。

**Architecture:** 显示驱动在本地初始化时覆盖 SPI 时钟分频，不改 SysConfig 自动生成文件。命令写入函数只在 DC 状态翻转后增加极短延迟，像素 RGB565 字节顺序与初始化表保持不变。

**Tech Stack:** MSPM0G3519、TI DriverLib、Keil ArmClang、ST7735S SPI LCD。

## Global Constraints

- 仅修改 `core/src/zf_device_tft180.c` 的 SPI 时序。
- 不修改 `empty.syscfg`、显示初始化命令、坐标偏移或引脚定义。
- 电脑端构建只能验证固件生成；花屏是否修复必须通过板端烧录确认。

### Task 1: 降低显示 SPI 时钟并稳定 DC 切换

**Files:**
- Modify: `core/src/zf_device_tft180.c:372-390,804-930`
- Test: `keil/Objects/empty_LP_MSPM0G3519_nortos_keil.build_log.htm`

**Interfaces:**
- Consumes: `SPI_0_INST`、`DL_SPI_setBitRateSerialClockDivider()`、`delay_cycles()`。
- Produces: ST7735S 在约 1 MHz SPI 下接收稳定的命令和 RGB565 数据。

- [x] **Step 1: 定义板端验收条件**

烧录后，白色背景必须覆盖全屏，`TI MSPM0 TFT180` 为红色，且屏幕不出现随机彩色块或条纹。

- [x] **Step 2: 实施最小驱动修改**

在 `tft180_init()` 的首个 LCD 命令前添加：

```c
DL_SPI_setBitRateSerialClockDivider(SPI_0_INST, 39);
```

在 `tft180_write_index()` 的两处 DC 状态翻转后分别添加：

```c
delay_cycles(8);
```

- [x] **Step 3: 重新构建固件**

在 Keil 中执行 Rebuild All。

Expected: 构建日志包含 `compiling zf_device_tft180.c...` 和 `0 Error(s), 0 Warning(s)`。

- [ ] **Step 4: 板端验证**

烧录新生成的 HEX，观察验收条件。若未通过，不再叠加初始化表改动，改为采样 SCLK/MOSI/DC 或运行四色诊断。
