# 分题循迹参数管理设计

## 目标

将每个题目的循迹 PID 与基础速度放入各自的 `LineController_t`。

当前建立第二问和第三问：第二问保存现有参数；第三问以第二问为初始值，作为当前蓝牙调参对象。

## 数据与运行逻辑

- `LineController_t` 增加 `base_speed`。
- `g_question2_line_controller` 保存 `Kp=5.20`、`Ki=0.0`、`Kd=0.002`、`base_speed=880`。
- `g_question3_line_controller` 在初始化时复制第二问的全部参数；随后独立保存自己的 PID、基础速度和 PID 历史。
- `g_active_line_controller` 指向当前选中的题目控制器；启动时默认指向第三问。
- 循迹更新使用活动控制器的 `base_speed`。切换题目时仅清空新活动控制器的积分和上次偏差，不修改其 PID 或基础速度。

## 蓝牙协议

- `2`：选择第二问。
- `3`：选择第三问。
- `P/p`、`I/i`、`K/k`（以及已有的 `D/d` 别名）：仅修改当前活动题目的 PID。
- `Q/q`：返回当前题号和该题目的 PID、基础速度。

数字 `3` 原有的速度档位动作不参与当前循迹控制，改为第三问选择命令。

## 边界与验证

- 不修改 PID 计算公式、灰度解析或电机控制接口。
- 参数仅保存于源码默认值和运行 RAM；不写入 Flash，重启后第三问再次从第二问复制。
- 新增静态契约检查：确认两个独立题目控制器、第三问复制初始化、默认第三问、蓝牙选题、活动控制器定向调参，以及循迹任务不再硬编码 `880`。
- 用户在 Keil 中完成最终编译；板上分别发送 `2`、`3`、`Q` 和 PID 调整命令验证两题参数互不影响。
